## Thay đổi nghiệp vụ/UI

1. POS có stepper 1–4, chọn sản phẩm trước, kiểm tra giỏ rồi khách/tiền, in sau khi server tạo đơn. Giữ cơ chế hóa đơn chờ và token chống thanh toán lặp đã có trong ZIP.
2. Thẻ POS hiển thị số biến thể/tổng tồn của sản phẩm. Dialog nêu tổng biến thể và tổng tồn; dropdown hiển thị giá/tồn riêng. Giỏ có cột Trong kho; server vẫn kiểm tra tồn tại thời điểm thanh toán.
3. Chi tiết sản phẩm admin tính tổng biến thể, số đang bán và tổng tồn qua toàn bộ biến thể, không đếm theo trang. Danh sách admin thêm cột Số biến thể; chi tiết cửa hàng hiện biến thể đang bán/tổng tồn của các biến thể đó.
4. Link Bán hàng online về trang chủ `/`. Hiển thị tên tài khoản, hồ sơ/đơn riêng với khách vãng lai. Giỏ thông báo đăng nhập là bắt buộc để đặt hàng, không tự tạo tài khoản ngầm.
5. Bỏ readonly của ô số lượng chi tiết; kiểm tra số nguyên trong giới hạn tồn. Checkout giữ trường người nhận có thể chỉnh; validate tên/email/điện thoại/địa chỉ/phương thức cả server và client.
6. Thêm token online checkout theo session và đồng bộ xử lý giỏ trong session. Gửi lại token của đơn đã tạo trả về cùng trang đơn, không tạo thêm hóa đơn; token sai yêu cầu kiểm tra lại.
7. Biến thể: chuyển kiểm tra size/chất liệu sang logic cho phép giá trị mới trước khi resolve, giữ chặn trùng bộ ba. Thêm giới hạn chuỗi; stock/price vẫn qua Bean Validation/service.
8. Nhân viên: guard username, ghi fullName/email/phone vào User trước INSERT, dùng luồng provisioning hiện có để sinh mật khẩu, BCrypt và gọi gửi mail ngoài transaction. Không thêm mật khẩu rõ vào response/log.
9. Bootstrap CSS/JS được vendored (MIT, xem `static/js/vendor/BOOTSTRAP-LICENSE.txt`). Có style chung green/white, controls thống nhất, POS/checkout responsive. Native select dùng cho chọn thanh toán/địa chỉ/biến thể POS để tránh xung đột dropdown tự tăng cường.

## Kiểm thử đã thực hiện

### Maven/JDK 17: 39 test, không lỗi

Chạy `mvn clean package` bằng image Maven 3.9.9 / Eclipse Temurin 17, qua mirror tải Maven Central dành riêng môi trường kiểm thử. Lệnh tương đương cho máy đã có Maven/JDK:

```text
./mvnw clean package
```

Artifact được tạo: `target/DemoDATN-0.0.1-SNAPSHOT.jar` (~58 MB). Không commit binary/target.

31 unit test có sẵn + 8 test `RefreshFlowTest` mới; tất cả qua. Các test mới dùng H2 MSSQL mode với Hibernate H2Dialect và MockMvc/Spring Security/Thymeleaf thật, nhưng mock AccountIssueRepository (các range-lock SQL Server), PosCatalogQuery và AccountMailService. Không gửi mail thật trong test.

| Kiểm tra regression | Kết quả quan sát |
|---|---|
| Khách chưa đăng nhập vào checkout | HTTP 302, Location `/login` |
| Header chưa/đã đăng nhập và chi tiết giày | HTTP 200; khác nội dung tài khoản |
| COD với người nhận hợp lệ | HTTP 302 đến đơn thành công; tạo đúng một đơn thuộc khách |
| Gửi lại token của đơn COD | HTTP 302 cùng đơn; số đơn không tăng |
| Điện thoại/email/địa chỉ sai, payment giả | HTTP 302 về checkout có BindingResult; giữ giỏ, không tạo đơn |
| Thêm size/chất liệu mới cho biến thể | HTTP 302; có biến thể mới với số lượng 7 |
| Thêm lại bộ ba bị trùng | HTTP 200 form có lỗi materialId, không tạo bản ghi thứ hai |
| Tạo nhân viên | HTTP 302 trang chi tiết; User có email/mustChangePassword; mock mail nhận đúng người nhận/username |
| Hiển thị POS | HTTP 200; thẻ mẫu có 1 biến thể, tồn 12 |
| Chuyển khoản online | HTTP 302, ban đầu UNPAID; tồn 12→10; admin xác nhận PAID, tồn vẫn 10 |
| Bán quầy tiền mặt | Thêm giỏ chưa tạo đơn/trừ tồn; checkout tạo PAID, tồn 12→10; gửi lặp không tạo đơn thứ hai; trang hóa đơn HTTP 200 |

Các hàng có liên quan được gộp trong 8 test method. Báo cáo Surefire nằm `target/surefire-reports/` trên máy chạy, không đưa vào Git vì có thể chứa thông tin request thử.

## Những phần KHÔNG được coi là đã kiểm chứng

- SQL Server native/import script và query count/locking/index: chưa chạy trực tiếp. Tải image SQL Server và gói Microsoft trả Forbidden ngay cả khi thử lại với quyền mạng bổ sung. H2 không thay được kiểm thử khóa SQL Server.
- Hai video YouTube tham khảo: endpoint truy cập trả 403. Không tuyên bố đã xem/đối chiếu toàn bộ video; thiết kế dựa trên ZIP và các lỗi/yêu cầu người dùng liệt kê.
- SMTP Gmail/Mailpit nhận thư thực tế: chưa test trong đợt này; test provisioning dùng mail mock. Cần cấu hình MAIL_* theo README và kiểm tra inbox trên máy người dùng.
- Tạo nhân viên trên database người dùng đang lỗi: cần schema đúng ZIP; không có kết nối máy người dùng để xác nhận nguyên nhân cục bộ đã hết. Không tự sửa/xóa dữ liệu thật.
- VNPAY/OTP không có trong ZIP nền này. Online hiện COD hoặc chuyển khoản thủ công, không tự xác nhận tiền thực, không gọi ngân hàng. Không trộn keys/config backend Vue cũ.
- Tài khoản mẫu, ảnh/sample catalog của ZIP chưa phải dữ liệu kinh doanh đã xác minh. Đổi mật khẩu demo/cấu hình ngân hàng trước triển khai thật.

## Database và khôi phục

- Không thêm bảng/cột trong đợt sửa này. Chỉ thêm COUNT_BIG trong query danh sách để hiển thị số biến thể.
- Bản khởi tạo đầy đủ được khuyến nghị: `database/init_shopbangiay_thu.sql`. Không import vào DB `f6s_shop` cũ.
- Ba bản full SQL được bỏ DROP DATABASE và chuyển sang báo lỗi + NOEXEC nếu database demo đã có, để tránh vô tình reset. Chưa xác nhận thực thi trên SQL Server thật; sao lưu trước mọi import. Không chạy các bản full nối tiếp nhau.
- Không xóa database/ảnh trên máy người dùng. Đổi nhánh Git không đổi schema/database. Muốn quay lại app cũ cần cả source cũ lẫn backup DB/ảnh tương ứng.
- Những `VERIFICATION_REPORT.md`/docs kiểm thử khác đi kèm ZIP là lịch sử bản nền, không phải bằng chứng rằng tất cả test cũ đã chạy ở đợt này. Native integration tests cũ chỉ chạy khi bật profile `sqlserver-tests` và cấu hình database thử riêng.
